# 三角色使用说明

Ming Harness 面向三类用户：管理员、老师、学生。三类用户使用同一个 Runtime 和同一个组织空间，但登录后进入不同的工作台；课程资料由老师维护，学生只消费被授权的课程内容。

## 登录方式

### 本地桌面演示

启动桌面端后，第一次进入会显示“选择进入方式”：

| 身份 | 演示账号 | 默认入口 |
| --- | --- | --- |
| 管理员 | `admin-demo` | 管理员治理中心 |
| 老师 | `teacher-demo` | 教师课程工作台 |
| 老师：从零开始开课 | `teacher-first-demo` | 没有资料和课程的首次开课路径 |
| 学生 | `student-demo` | 学生学习工作台 |
| 学生：第一次使用 | `student-first-demo` | 没有学习信息、课程和作业的学生空状态 |

演示登录只保存在当前浏览器/桌面的本地存储中，用于模拟不同用户。选择“老师：从零开始开课”或“学生：第一次使用”可以重复验证第一次进入系统的空状态路径；右上角可以切换演示身份或退出，切换后会重新加载当前工作台。

### 正式环境

正式环境不使用前端角色下拉框：

- API Key 模式使用 `Authorization: Bearer <key>` 或 `X-Api-Key`；
- 企业环境使用 OIDC/JWT；
- Runtime 从已验证的用户身份和权限推断产品角色，前端不能伪造角色。

角色与权限的关系是：

```text
认证身份 → 服务端权限 → 产品角色 → 工作台入口 → 页面可见性
```

一个正式用户可以同时拥有多个角色，例如“老师 + 学生”；系统以管理员、老师、学生的优先级确定主工作台，但资源权限仍由后端逐接口校验。

正式环境建议为三类账号发放最小权限：

| 角色 | 必要权限 | 主要可做的事 |
| --- | --- | --- |
| 管理员 | `ops.read`、`model.configure`、`context.configure`、`context.reindex`、`tenant.policy.*`、`auth.key.*` | 系统、模型、索引、组织策略、凭证和审计治理 |
| 老师 | `education.read`、`education.write`、`education.assign`、`education.evaluate`、`context.read`、`context.write` | 上传资料、维护课程元数据、开课、加入学生、布置、复核和反馈 |
| 学生 | `education.read`、`education.write`、`run.create`、`run.execute` | 建立画像、接受作业、学习、提交作业、查看证据和反馈 |

`context.write` 单独不会把普通上下文操作员识别成老师；老师角色必须具备课程运营或评价权限。管理员权限也不等于自动拥有某位老师的课程所有权，课程名单和作业仍按课程负责人绑定的用户 ID 校验。

## 管理员完整流程

1. 登录管理员账号，进入“管理员治理中心”。
2. 检查数据库、Redis、RabbitMQ、模型和 Worker 状态。
3. 在顶部配置大语言模型和向量模型。
4. 在“高级治理设置”中维护知识库索引、组织策略和 API Key 生命周期。
5. 在运行追踪中查看 Run、审批、重试、取消和审计证据。
6. 处理系统级问题，不直接替老师创建课程资料或替学生完成学习任务。

## 老师完整流程

教师进入系统后只处理课程运营，不需要先创建“学习者画像”或“结构化学习目标”；这些个人学习状态由学生账号维护。教师首页会按下面的顺序给出唯一主路径：课程资料 → 课程元数据 → 课程实例 → 学生名单 → 课程作业 → 复核与反馈。

### 1. 配置课程资料

进入“教师课程工作台”，按下面顺序操作：

```text
上传课程资料 → 维护课程元数据 → 创建课程 → 加入学生 → 发布作业
```

具体位置：

1. 点击“上传课程资料”，选择 PDF/DOCX；
2. 填写标题和可见用户，点击“上传并建立索引”；
3. 展开“课程资料维护入口”；
4. 选择刚上传的知识文档；
5. 填写学科、年级、课程版本、章节、知识点标签、前置知识和难度；
6. 点击“保存课程元数据”。

没有完成元数据绑定的文档不会被教育 Agent 当作课程来源。

### 2. 创建并发布课程

1. 展开“课程负责人入口”；
2. 填写课程代码、课程名称、学科、年级和课程版本；
3. 创建课程实例；
4. 在“活跃名单”中加入学生 ID；
5. 在“教师布置入口”中填写作业标题、说明、目标知识点、目标掌握度和截止时间；
6. 发布后，系统为每个活跃学生生成一份独立作业，并发送作业通知。

### 3. 复核学生结果

老师可以查看课程进度、学生作业证据、提交物和反馈。对已完成作业可以：

- 确认作业结果并填写量规评分；
- 退回返工；
- 要求补充证据；
- 建议重新学习或重试；
- 写入教师反馈。

## 学生完整流程

1. 登录学生账号，进入“学生学习工作台”。
2. 在“学习者画像与目标”中填写学科、年级、课程版本和学习目标。
3. 在“我的课程与学习路径”中查看老师加入的课程。
4. 在“我的课程作业与反馈”中接受新作业。
5. 点击“接受并开始”或“开始下一步”，进入课程约束下的学习对话；如果作业指定了编程语言，语言会随作业自动带入，学生不需要重复填写。
6. Agent 只检索匹配课程版本、知识点和难度的授权资料；它会把学习者掌握度投影到目标的知识依赖图，优先定位缺口最大的前置知识，再选择讲解、诊断、练习或复习。
7. 在作业提交区选择文字或代码；代码作业沿用教师冻结的语言，提交后可看到语法/编译评测状态和诊断。
8. 查看测评证据、掌握度、复习任务和教师反馈。代码通过只记为低权重形成性证据，不等同于概念掌握或教师评分。
9. 如果作业被退回返工、要求补证据或要求重试，直接从作业卡片上的下一步按钮继续。

学生不会看到模型配置、向量索引、API Key、组织策略和运行治理入口；这些能力属于管理员或老师的工作范围。

## 业务闭环

```text
老师上传资料
  → 课程元数据与课程版本
  → 创建课程并加入学生
  → 发布作业
  → 学生接受并启动教育 Run
  → 课程约束检索与分层教学
  → 作答、代码隔离评测、测评和提交物
  → 掌握度与学习目标更新
  → 教师确认 / 返工 / 补证据 / 重试
  → 复习任务与课程结果
```

如果课程资料、学习者画像、课程版本或形成性证据缺失，系统会在对应工作台显示阻断原因和下一步配置入口，不会退化为没有课程边界的通用问答。

管理员的实验面板会分别展示完整方法、去学习者状态、去知识依赖图和仅向量基线；当同一学习者—目标具备四种方法的形成性结果时，还会计算联合消融 interaction，帮助判断状态与依赖图是否存在协同趋势。该指标只用于实验诊断，不能替代随机分组、置信区间或显著性检验。

代码评测默认关闭。启用后，学生代码只进入独立 Docker 沙箱进行语法/编译检查：容器无网络、只读根文件系统、临时目录和资源上限，并丢弃 Linux capabilities；镜像使用 `--pull=never`，不会在提交时自动拉取。评测失败或沙箱不可用不会丢失提交物，评测诊断也不会自动转化为教师量规评价。
